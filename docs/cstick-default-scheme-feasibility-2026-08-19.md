# 확장 슬라이드 패드를 "기본값"으로 만들 수 있는가 — 가능성 검토 (2026-08-19)

**결론: 가능하다.** 세이브를 건드리지 않고 `code.bin` 패치만으로 CPP(듀얼 스틱)
조작을 기본으로 만들 수 있다. 안드로이드 Azahar처럼 세이브 파일에 손대기 어려운
환경을 위한 답이 된다. 다만 **메인 빌드의 기본값으로 넣으면 구형 3DS 사용자의
조작이 망가진다** — 별도 옵션 빌드로 내는 것이 맞다(§5).

검토 과정에서 **어제 만든 세이브 패처가 불완전했다는 것도 드러났다**(§4). 고쳤다.

## 1. 게임 내부 구조 — 전부 코드에서 확인

`code.bin`은 BLZ 압축이라 그대로 검색하면 아무것도 안 나온다
(`tools/nintendo_blz.py`로 풀면 5,264,144 → 8,478,720 B). 아래 주소는 **압축을 푼
이미지 기준**이며 VA = 파일오프셋 + 0x100000 이다. 기존 렌더러 패치 6곳
(`0x0015Exxx`/`0x0018xxxx`)과 같은 주소 공간이다.

### 컨트롤 프리셋 배열 — `0x0088F470`, 0x100 간격 4개

```
preset[0] @0x0088F470  id 0x80   CPP-off 세이브의 0x3C..0xF7 과 바이트 동일
preset[1] @0x0088F570  id 0x80   다른 조작 타입
preset[2] @0x0088F670  id 0x80   다른 조작 타입
preset[3] @0x0088F770  id 0x02   CPP-on 세이브의 0x3C..0xF7 과 바이트 동일
```

즉 **세이브의 컨트롤 블록은 이 프리셋을 그대로 복사한 것**이다. 어제 5개 세이브의
그룹 차분으로 얻은 33바이트가 실제로 preset[0] ↔ preset[3] 차이였음이 확인됐다.

### 프리셋 적용 함수 — `0x0012BD8C`

```
apply_scheme(idx):            ; idx >= 4 면 무시
    base = 0x0088F470 + idx*0x100
    config->scheme_index(+0x138) = idx
    for i in 0..0x2E:  config->control(+0x38)[i] = base[i]   ; 47 words = 188 B
    for i in 0x2F..0x3F: config->control[i] = 0
```

세이브는 `u32 CRC || config 구조체` 그대로다. 따라서 **config+X = 세이브 X+4**:
config+0x38 ↔ 세이브 0x3C(컨트롤 표), config+0x138 ↔ 세이브 **0x13C**(프리셋 번호).
CPP-on 세이브 3개 전부 0x13C = **3**, off 세이브 2개는 0이다. 어제 "정체 불명"으로
남겼던 옵션 블록 5바이트 중 0x13C는 이렇게 정체가 밝혀졌다.

### 게이트 비트와 강제 루틴 — `0x0010AEC0`

```
r1 = config->flags(+0x8)        ; = 세이브 0x0C
r0 = config->scheme_index       ; = 세이브 0x13C
tst r1, #1                      ; bit0 = "CPP 사용 중"
beq  ->  scheme_index != 0 이면 apply_scheme(0)     ; 비트가 꺼져 있으면 preset[0]로 되돌린다
else ->  scheme_index != 3 이면 apply_scheme(3)     ; 켜져 있으면 preset[3]로 강제한다
```

**이것이 핵심이다.** 컨트롤 표만 CPP용으로 바꿔 놔도 `config+8` bit0이 0이면
게임이 런타임에 preset[0]으로 되돌린다. 확인: 게이트 비트는 CPP-off 세이브 2개에서
0, CPP-on 세이브 3개에서 1이다(`0x00808000` vs `0x00908003`/`0x00908801`).

### 켜는 쪽 / 끄는 쪽

| 경로 | 주소 | 하는 일 |
|---|---|---|
| 켜기 | `0x0082C9F0` | `config->flags |= 1` (애플릿 절차 뒤) |
| 끄기 | `0x00116B50`, `0x001319A0`, `0x007FD6F4`, `0x007FDBDC` | `config->flags &= ~1` 후 `apply_scheme(0)` |

**끄는 쪽은 애플릿을 부르지 않는다.** Citra에서 먹통이 되는 건 **켤 때뿐**이라는
로그 관찰과 정확히 일치한다.

## 2. 그래서 무엇을 바꾸면 되는가

CPP "켜짐" 상태는 딱 세 가지다: **게이트 비트 + 프리셋 번호 3 + 컨트롤 표**.
셋 다 코드에서 만들어지므로, 코드에서 바꿀 수 있다.

| 방식 | 무엇을 고치나 | 크기 | 적용 범위 | 위험 |
|---|---|---|---|---|
| **A. 데이터만** | preset[0](188 B)을 preset[3] 내용으로 덮어씀 | 188 B, 명령어 수정 0 | 새 세이브·기존 세이브 모두(강제 루틴이 preset[0]을 적용하므로) | 낮음. 단 게이트 비트는 여전히 0이라 **비트를 읽는 다른 7곳**(메뉴 표시 등)은 "꺼짐"으로 본다 |
| **B. 강제 루틴 한 줄** | `0x0010AED8`의 `beq`를 `nop`으로 | 4 B | 세이브 무관, 항상 | 낮음. 메뉴는 "꺼짐"으로 보이는데 조작은 듀얼 스틱 — 표시 불일치 |
| **C. 상태 자체를 켬** | 부팅 시 `config->flags |= 1` + `apply_scheme(3)` | 코드 케이브 필요(기존 빌드도 code.bin이 200~400 B 늘어나 있음 = 이미 쓰는 방식) | 세이브 무관, 항상 | 중간. **실기에서 검증된 RT37 세이브와 완전히 같은 상태**가 되므로 동작 확실성은 가장 높음 |

권장은 **C**다. 근거: RT37 세이브가 2021년부터 Citra에서 동작한다는 것은
"게이트 비트 1 + 프리셋 3 + 표"라는 상태가 애플릿 없이도 게임에서 정상 동작한다는
실증이다. C는 그 상태를 코드로 만들어 낼 뿐이라 새로운 미지수가 없다.

## 3. 확실한 것과 아직 아닌 것

확실한 것:

- 프리셋 배열·적용 함수·게이트 비트의 위치와 의미 (코드 + 세이브 5개 교차 확인)
- 세이브 ↔ config 오프셋 대응 (+4)
- 이 상태 조합이 에뮬레이터에서 동작한다는 것 (RT37 세이브)

**해결됨 (2026-08-19):** 방식 C를 실제로 구현해 스테이징했고
(`tools/mgs3d_cpp_default_patch.py`, 24 B), **Azahar에서 오른쪽 스틱·CPP 동작
성공**했다. "게이트 비트 + 프리셋 3 + 컨트롤 표" 조합이면 애플릿 없이 충분하다는 뜻이다.
[`v0.9-cpp-test-staging-2026-08-19.md`](v0.9-cpp-test-staging-2026-08-19.md) 참조.

아직 아닌 것:

- 방식 A(데이터만)는 게이트 비트를 세우지 않으므로 여전히 미검증이다. 방식 C가
  통과한 이상 굳이 확인할 이유는 없다.
- 켜기 경로 `0x0082C9B8`의 `bl 0x0014B284`가 무엇을 확인하는지(신형 3DS 여부일
  가능성). 구현 단계에서 봐야 한다.
- 세이브 0x140·0x15C·0x162·0x168 4바이트(감도 추정)는 여전히 미상.

## 4. 부수적으로 드러난 결함 — 어제의 세이브 패처는 불완전했다

`enable-cpp`가 컨트롤 표 33바이트만 썼다. **게이트 비트(0x0C bit0)와 프리셋
번호(0x13C)를 쓰지 않았다.** §1의 강제 루틴이 그런 세이브를 preset[0]으로 되돌리므로
A/B 테스트는 십중팔구 "둘 다 안 됨"으로 끝났을 것이다.

고쳤다. 이제 `enable-cpp`는 게임의 켜기 경로와 같은 세 가지를 모두 쓴다.

```
enable  : 0x3C..0xF7 = preset[3],  0x0C |= 0x01,  0x13C = 3
disable : 0x3C..0xF7 = preset[0],  0x0C &= ~0x01, 0x13C = 0
```

`0x0C`는 다른 옵션 비트가 같이 사는 워드라 **비트 마스크로만** 손댄다(사용자의
`0x00808000`이 `0x00808001`이 된다). 왕복 검증 재실행: Normal·Hard·Extreme
on→off→on 3/3 바이트 동일, 사용자 세이브 off→on→off 바이트 동일, 프로파일 밖 변경 0.
`builds/cstick-test-2026-08-18/`의 A/B 세이브도 새 로직으로 다시 만들었다.
`show`는 이제 불완전한 세이브를 `INCONSISTENT`로 잡아낸다.

## 5. 안드로이드 관점 — 그리고 왜 "메인 기본값"이면 안 되는가

preset[3]은 **CPP 하드웨어를 전제로** `R→ZR`, `L→ZL`을 쓴다. ZL/ZR과 오른쪽
스틱은 신형 3DS(또는 CPP 장착 구형기, 에뮬레이터)에만 있다. 구형 3DS에서 이걸
기본값으로 강제하면 **사격 버튼이 없는 상태**가 된다.

따라서:

- 메인 한글 패치의 기본값으로 넣지 말 것.
- **별도 옵션 빌드**(예: `code.bin` 변형 하나)로 내는 것이 안전하다. 안드로이드·PC
  에뮬레이터 사용자와 신형 3DS 사용자가 그것을 쓰면 된다.
- 또는 구현 단계에서 신형 3DS 판별을 붙여 조건부로 강제한다(§3의 미확인 항목).

어느 쪽이든 **옵션 메뉴에서 켜는 행위는 여전히 애플릿을 부른다.** 기본값을 켜 두면
사용자가 그 메뉴에 갈 이유가 없어지지만, 경고 문구는 그대로 유지해야 한다.
