# v0.69 — safe staging (2026-08-14)

Scope, per instruction: prepare a byte-capacity-safe codec/movie/demo build and
place it in RomForge staging. **No CCI was built.** The final repack and
hardware/Citra test remain the user's step.

## What this fixes vs. v0.68

Two tool bugs found and fixed while verifying the capacity recheck
(`docs/capacity-recheck-2026-08-14.md`), both in `tools/mgs3d_script_compare.py`
and `tools/mgs3d_build.py`:

1. **CSV→JSON escaping bug** (`command_make_translation`): blindly
   re-escaped already-valid `<HH>` control tokens (the row's own trailing
   `<0A><00>`), corrupting 7,369/7,372 accepted codec rows into unparseable
   text. Fixed: only stray `<`/`>` outside a well-formed token are escaped
   now; the terminator is only appended if not already present; the dead
   line-rewrap block (referencing a nonexistent `game_raw_text` column) was
   removed. Full writeup:
   `docs/codec-review-csv-escaping-bug-2026-08-14.md`.
2. **Global glyph page never wired into the build.** `mgs3d_build.py`'s codec
   and movie/demo invocations predated the global Korean glyph page and used
   the old per-file glyph-append model. Added `--character-map` to
   `mgs3d_build.py` and `--character-map` to `make-translation`; movie/demo
   now get `--fixed-layout-reclaim --static-allocation` automatically when
   `--character-map` is set.

Verified empirically, not assumed: rebuilding codec with the fix now fails at
exactly the GCX and byte deficit the capacity recheck predicted (GCX 13, 355
bytes) — confirming both the fix and the capacity numbers agree with the real
build code.

## Master CSVs were not modified

`codec-3ds-INTEGRATED-review-direct-v2.csv`, `movie_natural_full.csv`,
`demo_natural_full.csv` are untouched by this task. All exclusions were
applied to **derived copies** under `translation/40_build_input/v0.69-safe/`
(gitignored, regeneratable from the masters + this doc).

## What was excluded and why

No donor reclaim was applied. No text was shortened. Every excluded row keeps
its original (pristine English) text for this build; nothing was reworded.

### codec — `codec-safe.csv` (7,043 / 7,372 accepted rows kept, 329 excluded)

| reason | rows | GCX | detail |
|---|---|---|---|
| MUST_SHORTEN | 215 | 22 | real byte overage, no reclaim possible (see capacity-recheck report) |
| REVIEW | 81 | 44 | would fit only if same-GCX donor text is blanked — reclaim not applied this round |
| BROKEN_TOKEN | 33 | (33 GCX, otherwise-safe) | pre-existing malformed `<...>` content (mostly leftover `<1fXX>`-style donor speaker tags) that fails `parse_rendered` regardless of capacity — unrelated to the escaping fix |

Every excluded row's whole GCX keeps its **original pristine text** for this
build (nothing partially applied within a GCX). Full list:
`translation/40_build_input/v0.69-safe/codec-excluded-rows.json`.

Verified after build: output codec.dat is byte-identical in size to the
source (67,204,976 B), all 2,326 GCX reparse with **zero layout drift**
(string/font offsets unchanged in every record), 0 new glyphs appended (all
Hangul resolved via the resident global page, as intended).

### movie — `movie-safe.csv` (588 / 689 rows kept, 101 excluded)

### demo — `demo-safe.csv` (1,920 / 2,228 rows kept, 308 excluded)

Both generated via the real `mgs3d_movie_tool.py capacity --max-safe-csv`
(per-entry maximal safe subset — matches the capacity-recheck PASS counts
exactly: 588 and 1,920). The coarser `--safe-csv` mode (whole-record,
excludes healthy neighbours of one bad entry) was **not** used since it
would have dropped far more than necessary; capacity is per-entry with no
cross-entry pooling here, so per-entry exclusion is the correct granularity.

Verified after build: `mgs3d_movie_tool.py audit-existing` safety gate
passed clean (0 conflicts) for both. Output files are byte-identical in size
to source (movie 229,376 B, demo 772,935,680 B), record counts unchanged
(108, 333), **zero subtitle-offset drift**, 0 bytes of font data appended
(global page covers everything, `--fixed-layout-reclaim` only donor-blanked
in place: 106/108 movie records, 325/333 demo records touched).
