## Build

`tools/mgs3d_clean_glyph_v1.py` could **not** be used to re-append the glyph
page: it resets every whitelisted partition0 file to the clean baseline first,
which would have destroyed the staged `code.bin`, DATs and `cache.hpk`. Since the
relocation changes neither the page's size nor its file position, the equivalent
minimal operation was used instead — overwrite the trailing `0xFF00` bytes, with
the old page verified in place and the offset re-derived via `page2_offset() + K`
rather than assumed. 169/169 preconditions held; 169/169 rewritten; sizes
unchanged.

**New tool: `tools/mgs3d_codec_safe_select.py`.** `build-korean
--preserve-record-layout` refuses to grow a GCX's fixed string region, so an
over-capacity record has to give rows back. The generator that produced
`v0.69-safe/codec-safe.csv` was never committed; this reconstructs it. Policy:
per failing GCX only, drop accepted rows in descending
`encoded_korean_bytes - original_bytes` order until the record fits, using the
shipped `replace_resources(preserve_layout=True)` as the fit test.

Result: 53 of 1,748 GCX overflowed, total deficit 607 bytes (gcx 13, the
264-entry encyclopedia index, was 298 of it). **175 units dropped, 8,478 →
8,303**, all 53 resolved. Note gcx 44 has literally zero slack — its string
region is exactly full — so both of its rows fall back to English; that is
correct, not a tool failure.

Against v0.69's 7,046 accepted codec units this is **+1,257 lines** in the build.

movie/demo were rebuilt with the new character map; their safe subsets are
unchanged (movie 588/689, demo 1919/2228) because their masters did not change.

Codec build reported `0 Hangul glyphs added` and `final_gcx_size_delta=0` — the
global page is doing the work and no record layout moved.
