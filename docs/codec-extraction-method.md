# codec 추출·검수 방법론

**이 문서에는 게임 대사가 인용되어 있지 않다.** 원문/번역문은 저작물이므로 저장소에
넣지 않는다. 여기에는 방법과 수치만 남긴다.

---

## 1. 아이콘 토큰 때문에 추출이 통째로 실패하던 문제

### 증상

3DS 조작 안내 문자열이 추출 대상에 아예 오르지 못했다. master에 행이 생기지 않으니
번역 대상 목록에도, 미번역 목록에도 나타나지 않았다.

### 원인

`strict_western()`이 `0x80` 뒤에 `0x7C`가 올 때만 통과시키고, 그 밖의 상위 바이트를
만나면 `return False`로 **리소스 전체**를 탈락시켰다.

3DS 버튼 아이콘은 2바이트 토큰 6개로 이루어진다.

```
80 23   A0 7B   A3 1E   80 <digit>   C0 7D   80 23
```

첫 `80 23`에서 두 번째 바이트가 `0x7C`가 아니므로 문자열 전체가 "서양 문자가 아님"으로
분류됐다.

### 아이콘 문법은 닫혀 있다

영문판 codec.dat 전수 측정 결과, 허용 범위를 넓게 잡을 필요가 없었다.

| lead | 뒤따르는 바이트 | 관측 |
|---|---|---|
| `0xA0` | `0x7B` | 16,981 / 16,981 (100%) |
| `0xC0` | `0x7D` | 16,981 / 16,981 (100%) |
| `0xA3` | `0x1E` | 16,815 / 16,815 (100%) |
| `0x80` | `#` 33,962 · 숫자 0–9 17,396 · `|` 528 | 12개 값으로 완전히 닫힘 |

그래서 상위 바이트를 일괄 허용하지 않고 위 조합만 열었다. 벗어나는 바이트가 하나라도
있으면 여전히 리소스 전체가 탈락하므로 일본어/바이너리 오탐 차단은 그대로다.

### 회귀 결과

| 항목 | 값 |
|---|---:|
| 구 정의 PASS | 571,385 |
| 신 정의 PASS | 584,954 |
| **손실 (구 PASS → 신 FAIL)** | **0** |
| 신규 인식 | 13,569 위치 / 316 문장 |
| 바이너리 쓰레기 오탐 | 0 |

## 2. coverage가 자기 자신을 검증하던 문제

기존 보고 `254,716 / 254,716, 부재 0`은 **계수 버그가 아니라 정의 구멍**이었다.

그 점검은 "English 리소스"의 정의로 `strict_western()`을 쓰면서 **분자와 분모 양쪽에
같은 술어를 적용**했다. 아이콘 리소스는 분모에서 이미 빠졌으므로 "부재" 목록에 오를
수조차 없었다. 두 수가 정확히 일치한 것은 같은 필터를 두 번 적용한 결과이지, 실제로 다
덮었기 때문이 아니다.

### 고친 방식

세 값을 **서로 다른 출처**에서 뽑고, 총계 뺄셈이 아니라 **집합 차집합**으로 계산한다.

| 값 | 출처 |
|---|---|
| `ACTUAL_CODEC_ENGLISH` | 바이너리만 — icon-aware parser + 코퍼스 유래 language ID |
| `MASTER_KNOWN` | master의 `gcx`/`resource` + `locations` 컬럼 |
| `MASTER_MISSING` | 위 둘의 집합 차집합 |

`MASTER_MISSING = 0`이 나온다면 필터를 두 번 써서가 아니라 바이너리의 모든 위치가
master 인덱스에서 실제로 발견됐다는 뜻이다.

**일반화:** 어떤 지표든 분자와 분모를 같은 술어로 만들면 그 술어의 사각지대를 영원히
볼 수 없다. 비율이 아니라 목록으로 검증하고, 출처를 분리한다.

## 3. donor 분리는 코퍼스에서 사전을 만들어 한다

수기 stopword 목록은 짧은 프랑스어/스페인어 문장을 영어 작업 큐로 계속 흘려보냈다.
그 탓에 한때 "미번역 542문장"으로 집계된 것이 실제로는 260문장이었다.

GCX 단위 비율도 쓸 수 없다 — 모든 GCX가 5개 언어 분기를 함께 담고 있어서, 영어
첫 무전이 들어 있는 레코드조차 리소스 기준으로는 74%가 donor다.

`tools/mgs3d_codec_langid.py`는 사전을 코퍼스에서 만든다.

- **donor 어휘** ← `<1F..>` 액센트 이스케이프를 가진 문자열(FR/ES/DE/IT 분기에만 등장)
- **영어 어휘** ← movie/demo 자막(donor 분기가 없어 깨끗함)
- 고유명사는 모든 분기에서 철자가 같으므로 증거에서 제외

codec master의 `english` 컬럼은 donor 오염이 있어 영어 방어 근거로 쓰지 않는다.

## 4. 화자 추론에서 쓸 수 있는 것과 없는 것

### 폐기한 방법

| 방법 | 커버리지 | 독립 대조 일치율 |
|---|---:|---:|
| 대화 시작 표지 전방전파 | 92 GCX | 18% |
| 앵커 ±3 화자 창 | 119 GCX | 48% |
| 고신뢰 앵커로 제한 | 18 GCX | 72% |

61~72%짜리 신호로 어체를 일괄 수정하면 게임에 오류를 심는 것이므로 쓰지 않았다.
이 추론에 의존하던 후보 30건도 적용하지 않고 사람 검수로 되돌렸다.

정보 카드(resource 0–13)도 화자 근거가 못 된다. 그 블록은 주파수의 헤더이지 그 대화의
화자가 아니며, 한 GCX 안에서 화자가 교체되는 경우가 실제로 있다.

### 검증을 통과한 방법

- **호격 규칙** — 영어가 상대의 호칭으로 시작하고 주인공을 부르지 않으면 화자는
  주인공이다. 화자가 명시된 줄에 적용해 7/7 적중.
- **확정 블록의 양쪽 어체가 같을 때** — 통화는 주인공 + 1인이므로, 상대가 반말 화자면
  줄별 화자를 특정하지 않아도 존댓말 줄은 오류로 확정된다.
- 단, 확정 블록이라도 통째로 한 화자로 가정하지 않는다. 실제로 한 블록의 뒷부분이
  다른 상대와의 대화였던 사례가 있었다.

## 5. 아이콘 토큰을 보존한 채 번역하기

번역문에 아이콘을 손으로 적지 않는다. 원본 리소스에서 아이콘을 **순서대로 뽑아 치환**
하므로 바이트와 순서가 구조적으로 보존된다.

줄바꿈도 손으로 배치하지 않는다. 영어의 토큰 스트림을 스키마(TEXT / `<0A>` / ICON /
`<00>`)로 읽고 한국어를 그 틀에 부어 넣으면, 방출되는 토큰 목록이 원본과 같아진다.
`tools/mgs3d_codec_icon_schema_fit.py`.

검증은 두 단계로 한다.

1. 표본 1건 round-trip — 원본 bytes → `render_bytes` → `parse_rendered` → 원본과 동일
2. 빌드 후 아이콘 보유 리소스 전수 대조 — 13,571건 검사, drift 0

## 6. 빌드 게이트

적용 전후로 다음을 모두 확인한다. 비율 하나로 PASS 처리하지 않는다.

- 기존 승인 번역 손실 0 · 기존 `korean` 손실 0 · `locations` 손실 0
- `(gcx, resource)` 중복 0
- token-map 밖 신규 glyph 0
- **모든 locations의 최소 슬롯** 기준 byte-fit (대표 위치 기준이 아니라 최소값)
- control-code 신규 drift 0 · 아이콘 토큰 drift 0 · `<00>` 종결 손상 0
- record size drift 0 · `block_start` drift 0 · 파일 크기 delta 0
- KO → EN 회귀 0
- HPK chain gate PASS

마지막으로 실기에서 확인된 위치를 **staged 바이너리에서 직접 decode**해 확인한다.

## 7. 저작권

- Konami의 원문 스크립트(영어/일본어), 대사집, 그 전사본은 **저장소에 넣지 않는다.**
- `translation/`, `docs/decisions/`, 대사를 포함한 evidence 파일은 `.gitignore` 대상이다.
- 문서에도 대사를 인용하지 않는다. 위치는 `gcx`/`resource` 번호로만 지시한다.
- 저장소에는 도구, 바이트 수준 포맷 기록, 집계 수치만 남긴다.
