# v0.9 — CPP 강제 패치 테스트 빌드 스테이징 (2026-08-19)

확장 슬라이드 패드(CPP) 조작을 **세이브 없이 코드로 강제**하는 패치를 스테이징했다.
CCI는 만들지 않았다. commit/push도 하지 않았다.

> **결과: 성공. 2026-08-19 Azahar에서 오른쪽 스틱과 CPP 동작 정상 확인.**
> 세이브를 건드리지 않고 코드만으로 CPP 상태를 만들 수 있다는 것이 실증됐다.
> 이에 따라 이 변경은 **최종 릴리즈의 에뮬용 산출물**에 들어간다 —
> [`RELEASE-PACKAGING-POLICY.md`](RELEASE-PACKAGING-POLICY.md) 참조.
> 개발 중에는 실기용/에뮬용을 분리하지 않으므로 이 staging을 그대로 유지한다.

**이후 모든 버전은 사용자 승인 없이 올리지 않는다** (2026-08-19 지시).

## 2. 패치 내용 — 24바이트, 코드 케이브 없음

도구: `tools/mgs3d_cpp_default_patch.py` (BLZ 해제 → 앵커 5개 검증 → 6워드 교체 →
BLZ 재압축 → 왕복 검증 → 스테이징). 이미 패치된 이미지에 다시 돌려도 안전하다.

엔진은 CPP 상태를 세 곳에 나눠 갖고 있고(`config+8` bit0 게이트 / `config+0x138`
프리셋 번호 / `config+0x38` 컨트롤 표), `0x0010AEC0`에서 **게이트 비트를 보고 나머지
둘을 다시 만든다.** 그 함수의 "꺼짐" 갈래(6워드)를 이렇게 바꿨다:

```
이전                              이후
0010AEF4  cmp r0, #0              ldr r0, [r6]            ; r6 = &config_ptr (0x0010AEC0에서 살아 있음)
0010AEF8  beq 0x0010AF10          ldr r1, [r0, #8]
0010AEFC  mov r0, #0              orr r1, r1, #1          ; 게이트 비트를 메모리에 세운다
0010AF00  bl  apply_scheme        str r1, [r0, #8]
0010AF04  nop                     ldr r0, [r0, #0x138]
0010AF08  nop                     b   0x0010AEDC          ; 진짜 "켜짐" 갈래로 합류
```

즉 **꺼져 있으면 켠다.** 합류 지점(`0x0010AEDC`)이 `cmp r0,#3 / movne r0,#3 /
blne apply_scheme(3)`이므로 프리셋 3과 컨트롤 표까지 게임 자신의 경로로 채워진다.
결과 상태는 실기에서 CPP를 켠 세이브(RT37, 2021년부터 Citra에서 동작)와 동일하다.

검증:

| 항목 | 결과 |
|---|---|
| 앵커 5개(`0x0010AED8/AEDC/AEE0/AEE4`, `apply_scheme` 진입부) | **5/5 일치** |
| 교체 전 6워드가 원본과 동일 | **일치** (아니면 거부) |
| 압축 해제 이미지 차이 | **21바이트**, 전부 `0x0010AEF6..0x0010AF0B` 안 |
| 글리프 패치 6곳 | **변경 없음** |
| 트램폴린 영역 `0x0087F8C4..0x008838C3` | **변경 없음** |
| BLZ 왕복 (`decompress(출력) == 패치 이미지`) | **OK** |
| 교체 구간으로 들어오는 다른 분기·점프테이블 | **없음** (`0x0010AED8`의 beq 하나뿐) |

## 3. 아자르 테스트 — 완료 (2026-08-19 성공)

리팩 후 실행, **오른쪽 스틱 카메라와 CPP 조작 정상 동작 확인.** 세이브를 미리
손댈 필요 없이 패치만으로 됐다. 아래는 재현·재검증용 절차로 남긴다.

RomForge로 리팩 → 실행. **세이브는 지금 쓰던 것 그대로 두면 된다** — 패치가
런타임에 상태를 만들기 때문이다.

1. 아자르 입력 설정에서 **ZL·ZR·오른쪽 스틱이 바인딩돼 있는지 먼저 확인.**
   CPP 스킴은 `R→ZR`, `L→ZL`로 바뀌므로, ZR이 없으면 사격이 안 된다(패치 문제 아님).
2. 게임 실행 → **오른쪽 스틱으로 카메라가 움직이면 성공.**
3. 안 움직이면 `builds/cstick-test-2026-08-18/A_basic_savedata`를 세이브 자리에
   넣고 다시 실행. 이걸로 되면 "강제 루틴이 안 돌았다", 이것도 안 되면
   "이 상태 조합만으로는 부족하다"로 원인이 갈린다.
4. **게임 안 확장 슬라이드 패드 옵션 메뉴는 열지 마라.** 켜는 동작이 여전히
   애플릿을 부른다(먹통). 패치는 그 메뉴를 없애지 않는다.

부작용으로 알아 둘 것: 이 빌드로 저장하면 **세이브에도 CPP 켜짐이 기록된다.**
원래대로 돌리려면 `code.bin` 백업 복구 + `mgs3d_save_tool.py disable-cpp <savedata>`.

## 4. 최종 배포에서의 위치 — 마지막 옵션

사용자 결정(2026-08-19): **이 패치는 마지막에 얹는다.** 최종 산출물이 CCI든 원본
패치(.3ds)든, 그 시점에 `code.bin`만 다시 패치해서 동작하면 된다. 위 도구는
스테이징된 `code.bin`을 입력으로 받으므로 어느 빌드에나 마지막 단계로 적용 가능하다.

배포 시 주의(변함 없음): preset 3은 ZL/ZR과 오른쪽 스틱을 전제한다. **CPP 없는
구형 3DS에서는 조작이 망가지므로 기본 빌드에 넣지 말고 별도 옵션 빌드로** 내야 한다.
근거는 [`cstick-default-scheme-feasibility-2026-08-19.md`](cstick-default-scheme-feasibility-2026-08-19.md) §5.
