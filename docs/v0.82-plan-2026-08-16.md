## Why the worklist went 586 → 301 applied → 302 remaining

The worklist is not "previous list minus what was applied". It is recomputed each
round as *every accepted line the current build leaves out*, so the arithmetic has
to be checked by set difference, not subtraction.

Sets: `old` = lines excluded under v0.80, `new` = excluded under v0.81,
`applied` = the 301 rows written this round.

| | rows | codec | movie | demo |
|---|---:|---:|---:|---:|
| A. edited, now in the build | **284** | 138 | 20 | 126 |
| B. edited, still excluded | **17** | 0 | 1 | 16 |
| C. never edited, still excluded | **285** | 38 | 80 | 167 |
| D. never edited, yet now included | **0** | 0 | 0 | 0 |
| E. newly excluded (absent from the old list) | **0** | 0 | 0 | 0 |

`586 − 284 = 302` ✓ and `301 − 284 = 17` ✓.

**No row was newly added and none was reclassified.** The entire +17 is class B:
lines that were edited but still do not fit.

## Why those 17 still do not fit

Every one of them was shortened to land *exactly* on the budget the worklist
showed. The movie/demo encoder needs 1–2 bytes more than the raw encoded length
(terminator/padding), so a line that measures exactly at budget is still one byte
over in the builder's own accounting:

| row | worklist says | encoder says |
|---|---|---|
| `demo@17222088` | budget 4, used 4, over 0 | needed 5, capacity 4 → **deficit 1** |
| `demo@107699772` | budget 55, used 55, over 0 | needed 57, capacity 56 → **deficit 1** |

Every row shortened with any slack passed. So the defect is in
`tools/mgs3d_dialogue_worklist.py`'s budget model for movie/demo, not in the
edits.

## Correction to a wrong model, recorded so it is not repeated

While investigating, the capacity report's record-level `safe: false` flag
suggested that one over-budget entry rejects a whole subtitle record, which would
have made "fix one line, gain eight" the right targeting strategy. **That is
wrong.** The build uses `--max-safe-csv`, which drops individual rows, and the
excluded rows match the deficient entries one-for-one:

| record | accepted rows | rows still excluded | entries with a deficit |
|---|---:|---:|---:|
| demo 8 | 8 | 1 | 1 |
| demo 85 | 10 | 2 | 2 |
| demo 42 | 7 | 1 | 1 |

So exclusion is per row. Record-level aggregates must not be used to plan this
work.
