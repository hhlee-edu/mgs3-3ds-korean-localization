# vox 도너 교차 검증 (2026-08-22)

`python tools/mgs3d_vox_donor_check.py`

## vox는 외부 자료가 필요 없다

`mgs3d_crossvalidate.py`는 shinsnote 정렬에 기대는데 **vox에는 그게 안 먹는다.**
shinsnote 완전일치 135건을 열어보면 중앙값 2글자, 129건이 5자 이하 —
`Ah.`→`아.`, `Hmm.`→`음...` 같은 우연이다. shinsnote는 컷신·무전 대본이지
게임 중 병사 대사집이 아니다.

그런데 **vox.dat은 자기 안에 더 좋은 기준을 갖고 있다.** 큐 하나에 EN +
FR/DE/IT/ES가 같은 타이밍으로 들어 있다 — 모든 줄에 전문 번역 4개가 완벽히
정렬된 채로 존재한다. GameFAQs도 shinsnote도 필요 없다.

```
큐 3,983 → 번역 CSV와 대조된 큐 3,845 (96.5%)
```

## 검출기

| | 근거 | 결과 |
|---|---|---|
| `V1-token` | 숫자·호출부호가 EN과 도너 다수에 있는데 KO에만 없음 | 1건 (오탐 — `17`→`열일곱`) |
| `V2-terse` | 다섯 언어가 문장 N개인데 KO만 훨씬 적고 실제로 짧아짐 | 2건 |
| `V3-lines` | 줄바꿈이 사라져 한 줄이 영어 최장 줄보다 넓어짐 | **31건** |

**실질은 V3다.** 예:

```
EN  "have both been wiped out / without a trace..."   최장 줄 폭 24
KO  "둘 다 흔적도 없이 사라졌다..."                     한 줄, 폭 36   <- 넘침 위험
```

vox 자막은 슬롯 예산(`max_bytes`)은 통과해도 **화면에서 가로로 넘칠 수 있다.**
바이트가 맞는 것과 화면에 들어가는 것은 다른 문제다.

`donor-check-linebreak-proposals.csv`에 30건의 자동 줄바꿈 제안이 있다
(1건은 공백 경계가 없어 수동). 전부 폭이 영어 최장 줄 이하로 떨어진다.

## 이 도구가 만들어지며 고친 것

처음 판은 175건을 뱉었고 대부분 오탐이었다. 세 번 조였다.

1. **`SNAKE` 오탐 36건.** 대문자 토큰이 한국어에 없으면 손실로 봤는데,
   「스네이크」로 음역한 것이었다. → 토큰별 **유지율**을 재서 과반이 라틴으로
   유지될 때만 보존 대상으로 본다. 학습 결과가 정확하다:
   `ADAM CIA CQC EOD KGB LIFE MAP RPG SPECIAL SVD TNT`.
2. **문장 수만 보면 정상 번역이 걸린다.** 한국어는 문장을 쉼표로 합친다
   (`Huh. A bird...` → `흠, 새네...`). → 문장 수 감소 **AND** 실제 길이 손실을
   함께 요구. 31 → 2건.
3. **줄 수 불일치는 방향이 중요하다.** 줄이 *늘어나는* 건 무해하고(더 짧게 접힐
   뿐) *줄어드는* 것만 위험하다. → 감소 방향 + 폭 증가만. 108 → 31건.

## 적용은 아직 안 했다

vox.dat 재삽입은 `tools/mgs3d_vox_extract.py apply`를 거치고 124MB 파일을 다시
빌드·스테이징해야 한다. 제안 CSV만 만들어 뒀다.

`extract`를 다시 돌리지 말 것 — 번역이 든 CSV를 덮어쓴다.
