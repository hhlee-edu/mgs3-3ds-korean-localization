## 범위

지시대로 **CPP 패치는 제외**했다. 1.1은 CPP enforcer를 재작성했고 1.0 패턴이
이미지 전체에 0회 존재하므로, 억지 이식 대신 1.1 기준 재분석 후 별도 패치로 간다.

이식한 것은 네 가지뿐이다.

## 정적 검증 — 27/27 통과

`python tools/mgs3d_port_v11_glyph.py verify`

주요 항목:

- 해제 크기 **8,744,960 B로 불변** → **exheader 수정 불필요**
- 변경 범위: **7곳, 실제 변경 671 B**. 그 외 이미지 전체 무변경

  세 숫자가 서로 다른 것을 재므로 구분해서 적는다.

  | 값 | 의미 |
  |---:|---|
  | **816 B** | 케이브 예약 구간 `0x330`, VA `0x008A8104..0x008A8434` |
  | **815 B** | 그 안에서 기록이 닿는 범위 (`+0x000..+0x32E`). 마지막 바이트 `+0x32F`는 순정과 패치본 모두 0이라 diff에 잡히지 않는다 |
  | **647 B** | 케이브에서 **실제로 값이 바뀐** 바이트. 케이브 내부에도 0인 바이트가 169개 있고, 착지 구역이 원래 0이므로 그만큼은 변경으로 잡히지 않는다 |

  ```
  671 = 24 (훅 6 x 4 B) + 647 (케이브)
  816 = 647 (변경) + 169 (케이브 안의 0 바이트)
  ```

  즉 "케이브 815 B"는 변경 바이트 수가 아니라 기록 범위의 폭이다. 변경 바이트로
  합산할 때는 **647**을 써야 671과 맞는다.
- 케이브 착지 구역이 순정 1.1에서 전부 0임을 사전 확인, `.text` 패딩(3,836 B) 내 수용
- 케이브 분기 **44 internal + 12 external 전부 정상 해석**
- 리터럴 4개 전부 목표값 일치, 두 심볼이 1.1의 올바른 세그먼트(.data/.bss) 내에 위치
- 앨리어스 `cmp` 즉값 = `{0x84, 0x87, 0xA4, 0xA7}` — A0/A3 잔존 없음
- **CPP enforcer 구역(`0x0010A000..0x0010B400`) 순정 1.1과 바이트 동일**
- BLZ 라운드트립 검증 통과 (재압축본을 다시 풀어 원본과 일치)

### 도구와 독립적으로 재확인한 항목

도구가 자기 로직을 검증하는 순환을 피하기 위해 별도 스크립트로 다시 확인했다.

- 순정 1.1 대비 diff가 정확히 위 7구간뿐임
- 각 훅이 올바른 케이브 진입점으로 분기함
- **각 훅의 원본 명령어가 케이브 폴백 경로에서 동일 레지스터로 재실행됨** (6/6)
  — 조용히 틀릴 수 있는 지점이라 별도로 확인했다. 예: 훅 `0x0015E758`은
  `bic r1,r9` 이므로 케이브 `+0x1FC`도 `r9`여야 하고, 실제로 그렇다.

첫 시도에서 이 검사가 2건을 MISMATCH로 표시했으나, 해당 위치는 fallback이 아니라
조건부 조기 복귀(`cmp r2,#0; bne` / `add r0,r0,#1; b`)였다. 검사 쪽 오류였고
패치는 정상이다.
